1
Positioning LLMs inside Real Workplace Tasks
25 min · Light concepts
+
The session begins with a realistic, pressure-filled workplace situation where multiple outputs are due under tight deadlines and the input materials are incomplete and conflicting.
The content covers which day-to-day tasks benefit from LLM support — such as summarisation, structured output generation, rewriting, and drafting short professional deliverables.
The content also clarifies where human judgment still remains essential, and why LLMs cannot replace the clarity that comes from deciding what a task actually requires before any drafting begins.
This section ends with a practical view of which workplace tasks are suitable for LLM support — and which are not yet ready for it because the inputs are too ambiguous.
Instructors use the campaign scenario to make this concrete: trainees read real-seeming messy documents — incomplete briefs, conflicting audience definitions, vague deadlines — and identify what needs to be resolved before any AI tool is opened.
2
Defining the Manual Standard Before Prompting
25 min · Light concepts
+
The session moves into defining what a strong output looks like before the first prompt is written — establishing the expected structure, criteria, and reader requirements for each deliverable.
The content covers how to name the task, identify the reader, specify the required format, and list the criteria that will later be used to judge whether the AI-generated output is usable.
The content also focuses on the distinction between outputs that look complete and outputs that are complete — a distinction that only shows up when you have a clear standard to test against.
This section ends with a manual benchmark — a documented quality standard for the first output — that makes later AI output easier to evaluate accurately.

What makes a strong output? — Click to explore

The reader is clearly identified
Tap to see why this matters
An exec update for a director and a manager summary for a team read differently. If the reader is vague, the AI will write for no one in particular — and the output will feel generic even if the content is technically correct.
The format is specified precisely
Tap to see why this matters
Length, heading structure, tone, and level of detail are all format decisions. If you do not specify them in the prompt, the model will choose — and it may choose wrong. The manual standard captures these before drafting begins.
The facts are confirmed before prompting
Tap to see why this matters
AI can only work with the inputs you provide. If you feed it ambiguous or unverified information, the output will reflect that ambiguity — with high confidence. Fact-checking happens before the prompt, not after.
3
Building the First Prompt Workflow
35 min · Medium complexity
+
The session focuses on prompt construction as a structured workflow rather than a single ad-hoc message — choosing the right first task before writing any prompt.
The content covers the six-part anatomy of a well-constructed prompt: task framing, context, instructions, output format, constraints, and verification conditions.
Trainees first diagnose a weak prompt and identify what it is missing, then build the correct prompt part by part — assembling each component deliberately before running it.
This section ends with a complete, repeatable prompt workflow — ready for live use on the first workplace task.
Anatomy of a well-built prompt
Task: What you are asking the model to produce
Context: Reader, purpose, deadline, known constraints
Facts: Only verified information — confirmed before prompting
Format: Structure, length, headings, tone requirements
Limits: What not to include. What to mark as pending.
Verify: The criteria you will use to judge the output
Try It Yourself

Before the session builds the prompt together: Which task should the team tackle first? Consider — which output has the clearest reader, the most verifiable facts, and the easiest quality standard to check? That is your starting point.

4
Generating Outputs and Reviewing Prompt Versions
30 min · Medium complexity
+
The session moves into live output generation — three different AI-produced drafts of the same output appear, all plausible at first glance.
The content covers prompt iteration: trainees compare multiple draft versions side by side and trace each quality difference back to a specific prompt decision that produced it.
The content also focuses on how to read AI output critically — identifying which draft is genuinely stronger and why, rather than accepting the first result that sounds polished.
This section ends with a chosen working draft and a clearer understanding of why some prompts produce stronger outputs than others.

What a weak draft looks like

Produces content that sounds fluent but contains unverified claims, missing format structure, and audience misalignment. It reads well on first pass and fails on review.

  • No clear confirmed / pending distinction
  • Tone does not match the reader's seniority
  • Action line is vague or missing entirely

What a partial draft looks like

Has some structural strengths — sections are labelled, the format is close — but the factual base is not verified and the action line still leaves the reader interpreting rather than deciding.

  • Structure is present but content inside it is shaky
  • Open items presented as facts
  • "No action required" without specifying under what conditions

What a strong draft looks like

Confirmed facts are separated from open items. The action line is specific. Format matches the reader's role and time pressure. Pending items are flagged — not buried or softened.

  • Confirmed / Pending clearly separated
  • Honest about what is still unresolved
  • Reader can act without a follow-up conversation
5
Evaluating Outputs with Test Cases and Scoring
35 min · Medium complexity
+
The session focuses on evaluation — applying a structured scoring rubric to the working draft rather than accepting it because it looks complete.
The content covers six evaluation criteria: clarity, completeness, accuracy, format control, usefulness, and overall verdict.
The content also covers stress-testing: placing the draft in a simulated real-world scenario (a director walking into an exec meeting) to test whether it holds up under pressure.
This section ends with a formal review verdict — and a revision list if the draft does not pass all criteria cleanly.
Scoring principle: "Being the best of three drafts is a low bar. The question is not which draft is best — it is whether this draft clears the actual bar for this specific reader and deadline."
6
Building a Multi-Step Workflow: Generate → Critique → Revise → Verify
40 min · Tool-heavy
+
The session shifts from one-step prompting into a complete, repeatable LLM workflow — using the revision list from evaluation as the starting point.
The content covers each stage in sequence: generating the initial output, critiquing it against the rubric, deciding what to keep / change / remove, and producing a revised candidate that is genuinely stronger.
The content also covers fallback logic — what to do when the first response does not meet the standard, and how to decide whether revision is worth attempting or a new prompt is needed.
This section ends with a revised candidate output and a clear understanding of the difference between a one-prompt result and a properly controlled workflow.

What each stage of revision decides

What to Keep
Tap to reveal
Structure that works. Sections that are factually clean and reader-appropriate. Format choices that match the standard. Revision should protect what is already right — not rewrite everything.
What to Change
Tap to reveal
Lines that are technically present but still leave the reader interpreting. Vague action statements. Open items that are not clearly labelled as open. Wording that misrepresents the current status.
What to Remove
Tap to reveal
Details that clutter the output for the wrong reader. Operational specifics that belong in a different document. Anything that forces the reader to interpret information that should have been resolved before prompting.
7
Applying Privacy, Hallucination, and Safe-Use Checks
25 min · Light concepts
+
The session focuses on the guardrails required for responsible workplace use — establishing a verification mindset before any output leaves the team.
The content covers three categories of risk: hallucination, privacy exposure from including identifiable or sensitive information in prompts, and the conditions under which AI output must be reviewed by a human before it is used.
The content also covers the send decision: given verified and unverified items in the output, trainees practice choosing between sending as-is, holding for one fact, or sending with a cover note that adds the missing context.
This section ends with a safer decision process for accepting, revising, or rejecting AI-generated content — and a clear picture of where the human is always responsible.
Check Type What It Covers Status
Hallucination Every factual claim is traceable to a confirmed source in your inputs Flag if missing
Privacy No personally identifiable or sensitive information entered the prompt Flag if present
Pending items Unverified items are clearly labelled — not presented as confirmed facts Required
Human review A person with decision-making authority has read and approved the output Always last
8
Comparing Free and Paid Tooling in Practice
20 min · Light concepts
+
The session moves into a practical side-by-side comparison of free and paid LLM environments — grounded in the outputs already produced during the session, not in general advertising claims.
The content covers differences in output quality, response speed, format control, multi-step workflow support, and the conditions under which a paid tool provides meaningfully better value for a specific task.
This section ends with a grounded decision framework for choosing tools intentionally — rather than defaulting to the most familiar or cheapest option for every task.
Free Tools — When they work
Single-step tasks with a clear, constrained output
Light drafting where the stakes of a weak response are low
Exploration and experimentation before committing to a workflow
Paid Tools — When they add value
Multi-step workflows requiring consistent format control
Longer context — full campaign packs, detailed briefing documents
Higher-stakes outputs where revision cost exceeds tool cost
9
Using AI to Produce Structured Workplace Outputs
25 min · Tool-heavy
+
The session closes by applying the complete workflow to a second, harder type of output — persuasive public-facing copy, where the verification criteria shift from factual accuracy to audience fit and brand safety.
The content covers how the same four-stage pattern (generate → critique → revise → verify) applies to summaries, action plans, structured tables, short reports, social copy, and professional drafts — with different evaluation criteria for each output type.
The content also focuses on what changes when the output is persuasive rather than informational: the rubric becomes less about factual checking and more about resonance, reader fit, and brand approval readiness.
This session closes with a complete, reviewable LLM-assisted workflow — prompt versions, evaluation notes, verified output, and a human send decision — ready to apply to any future workplace task.
Same workflow, different criteria: "Sounds good" is not a passing grade for public-facing copy. The correct bar is: "Does this resonate with the right person, and would it pass brand review on first read?"
Try It Yourself

Before running the LinkedIn post prompt: What is the single most important decision to lock in before drafting? The audience choice, the message angle, or the tone register? What happens to the output if you get that decision wrong?
